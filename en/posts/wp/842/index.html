Docker Cheat Sheet

posted: 2017-11-28

Docker

Logging In to Docker Hub

You have to do this first, or you can’t pull images published on Docker Hub.
* Requires a Docker Hub account

docker login

Building a Docker Image

Build an image from a Dockerfile.
How to write a Dockerfile itself is out of scope.

docker build --no-cache=true -t {image name of your choice} {path to directory containing the Dockerfile}

Listing Local Images

docker images

Creating a Container from an Image

docker run -itd -h {hostname of your choice} -v {host directory}:{container directory} --name {container name of your choice} -p {host port}:{container port} {image name} {command to run}

■Notes
[v option]
Shares a host directory with a container directory.
For example, -v /home:/home syncs the contents of the host’s home directory and the container’s home directory.

[p option]
Sets which container port receives traffic arriving at which host port.
For example, -p 80:80 forwards access to host port 80 to container port 80.
To set multiple ports, you can specify the option multiple times, like -p 80:80 -p 443:443.

You can also specify an IP address, like -p 192.168.1.1:80:80, for example when the host has multiple IP addresses.

[Command to run]
Can be omitted if the command is specified in the Dockerfile.
If you don’t need to run a specific command, specifying /bin/bash is a safe choice.

Listing Containers

docker ps -a

Without the -a option, stopped containers are not shown.

Entering a Container from the Host

docker exec -it {container name} {shell}

■Notes
[Shell]
Which shell you want to log in with.
If you’re not sure, bash is a safe choice.

Stopping a Container

docker stop {container name}

Starting a Container

docker start {container name}

Removing a Container

Run the following while the container is stopped.

docker rm {container name}

Removing a Local Image

Run the following when no container is using the image.

docker rmi {image name}

Backing Up a Container

docker export {container name} > {backup name of your choice}.tar

Restoring a Container from a Backup

Restoring a container means creating an image from the backed-up container.
Creating a container from that image completes the restore.

cat {backup name}.tar | docker import - {name of image to create}  
docker run ~rest omitted~

Transferring Files Between Host and Container

# Host to container  
docker cp {source file path} {container name}:{destination file path}  
# Container to host  
docker cp {container name}:{source file path} {destination file path}
