[Let's Encrypt] How to Use Certbot (CentOS 7 + nginx)

posted: 2017-06-12

CentOS
Nginx

■Environment

CentOS 7.3
nginx 1.10.3
certbot 0.14.1

■Issuing the initial SSL certificate

Install certbot.

yum -y install yum-utils  
yum install certbot  

# If you are installing certbot on CentOS 6 or AWS EC2, use the following steps.
curl https://dl.eff.org/certbot-auto -o /usr/bin/certbot-auto  
chmod 700 /usr/bin/certbot-auto  
ln -s /usr/bin/certbot-auto /usr/bin/certbot  
# You can use certbot-auto as is, but I create a symbolic link
# to stay consistent with the steps below.

Issue the certificate

certbot certonly --webroot -w /usr/share/nginx/html -d your-domain.com

*Adjust the command above to your environment.
/usr/share/nginx/html
　→The document root of the domain to configure
your-domain.com
　→The domain to configure

[Note]
As of November 2017, the –debug option was required for the above command on AWS EC2.
Some pages say “–debug” is no longer needed on EC2 either,
so it may depend on the environment (?).

The certificates are now generated in the following directory.

ll /etc/letsencrypt/live/your-domain.com/  
lrwxrwxrwx 1 root root  40 Jun 12 16:41 cert.pem -> ../../archive/your-domain.com/cert1.pem  
lrwxrwxrwx 1 root root  41 Jun 12 16:41 chain.pem -> ../../archive/your-domain.com/chain1.pem  
lrwxrwxrwx 1 root root  45 Jun 12 16:41 fullchain.pem -> ../../archive/your-domain.com/fullchain1.pem  
lrwxrwxrwx 1 root root  43 Jun 12 16:41 privkey.pem -> ../../archive/your-domain.com/privkey1.pem

Each time the certificate is renewed, these symbolic links are switched to point to the new certificate,
so once you configure nginx, you never need to change it.

■nginx settings

Configure the SSL certificate and private key in the nginx configuration file.
(/etc/nginx/nginx.conf)

(omitted)  
server {  
    listen  443 ssl http2 default_server;  
    (omitted)  
    ssl_certificate "/etc/letsencrypt/live/your-domain.com/fullchain.pem";  
    ssl_certificate_key "/etc/letsencrypt/live/your-domain.com/privkey.pem";  
    (omitted)  
}

After configuring, restart nginx.

systemctl restart nginx.service

■Setting up automatic SSL certificate renewal

Once less than one month remains before the SSL certificate expires, it can be renewed.
Renew it with the following command.

certbot renew

Register the above command in cron so it renews automatically.
As an example, run the renewal early every Monday morning.
(If more than one month remains, it does nothing and exits.)

10 0 * * 1 /bin/certbot renew && /bin/systemctl reload nginx.service > /dev/null 2>&1

※※※ Caution ※※※
Renewing the certificate alone won’t take effect unless nginx reloads it.

*Added February 2020
As of certbot ver 1.0.0, you can specify a command to run after renewal with an option like this:
/bin/certbot renew –post-hook “systemctl restart nginx.service”

The setup is now complete.

■Deleting an SSL certificate

To delete the SSL certificate for a domain you no longer need, run the following command.

certbot revoke --cert-path=/etc/letsencrypt/archive/your-domain.com/cert1.pem

This revokes the SSL certificate and also removes it from automatic renewal.
