Using Multiple GitHub Accounts with the git Command

posted: 2018-11-14

git

Environment

Mac OS
(Probably works on Linux too)

* Added 2019/3/29

It turns out GitHub’s Terms of Service prohibit one person from operating multiple free accounts.
https://help.github.com/en/articles/github-terms-of-service#b-account-terms

If you are using multiple free accounts, consider merging them.
This guide may still be useful for cases like switching between a free account and a paid account.

Overview

On GitHub, private keys are tied to accounts,
and when you run the git command, the account is determined by the private key you specify.
(If no private key is specified, the default private key is used)

As a freelancer, I sometimes need a client’s GitHub account
separate from my own, but
using multiple GitHub accounts on one PC makes switching private keys a hassle.

At first I configured them as separate hosts in .ssh/config, as in this article,
but then I had to rewrite the host name every time I cloned, etc.,
which was also a bit of a hassle. (Especially since the project had lots of repositories)
https://qiita.com/yamataku29/items/4744c9c70ad793c83b82 (Japanese)

So I wrote a script that, once you map repository owners (users or Organizations) to private keys,
automatically picks the right private key when you run git commands.

Here it is
https://github.com/mildjester/gits

Usage

(1) Download the repository above, either by cloning or as a ZIP.

(2) Copy config_template to config in the same directory.

(3) Set the following variables in the newly created config
■defaultKey
Path to the default private key. The template value should basically be fine.

■specialKeys
A list mapping repository owners that use a non-default private key to their private keys.
The format is “repository owner::private key path”, so
for example, if repositories of “owner AAA” use ~/.ssh/id_rsa_1
and repositories of “owner BBB” use ~/.ssh/id_rsa_2,
it looks like this.

specialKeys=(  
    'AAA::~/.ssh/id_rsa_1'  
    'BBB::~/.ssh/id_rsa_2'  
)

(4) Add the following alias to ~/.bashrc.
If your usual shell isn’t bash (zsh, fish, etc.), add it to that shell’s config file instead.

# Replace the git command  
alias git="/path-to-gits-repository/gits.sh"

*Replace path-to-gits-repository with the directory where you cloned or downloaded the repository

Now you can type git commands without thinking, and the private key is switched automatically behind the scenes.

Note: If You Use ghq

I use ghq get more often than git clone, so I prepared a script for that too.
The basic configuration is the same as above; just add an alias.

alias ghq_get="~/git/github.com/mildjester/gits/ghq_get.sh"

This doesn’t fully replace the command,
but you can fetch repositories with the following command.
(The only difference is an underscore instead of a space between ghq and get)

ghq_get git@github.com:AAAA/hogehoge.git
