Running a Vue.js App with forever

posted: 2017-07-31

CentOS
node

■Environment

CentOS 7.3
npm 3.10.10

=====Added 2017/12/27=====
When I tried these steps again after a long time,
build/dev-server.js no longer existed in the vue project,
so it could no longer be started with forever.
It’s probably better to start it with npm start or similar, following the official docs.
===End of addition=====

■Steps

If npm and nodejs aren’t installed, install them with yum.

yum install npm nodejs

Install “vue-cli”, a tool for easily setting up vue apps,
and “forever”, which can run node apps like daemons.
*These are installed globally, so add the “-g” option.

npm install -g vue-cli forever

Create the project directory.
Run the following in the directory where you want to create the project:

vue init webpack samplevue    
*"samplevue" is the name of the directory you want to create

After running the above, you’ll be asked various questions; answer them according to the environment you want.
Here is an example:

? Project name samplevue  
? Project description This is Sample  
? Author Djiro  
? Vue build standalone  
? Install vue-router? Yes  
? Use ESLint to lint your code? No  
? Set up unit tests No  
? Setup e2e tests with Nightwatch? No  
? Should we run `npm install` for you after the project has been created? (recommended) npm

Move into the created directory and install the required files.

cd samplevue    
npm install

At this point, the vue app can be started with forever.
To start it in the dev environment, use the following command:

forever start build/dev-server.js

The js file specified here is listed around line 7 of “package.json” directly under the project directory you created.

{  
  "name": "samplevue",  
  "version": "1.0.0",  
~snip~  
  "scripts": {  
    "dev": "node build/dev-server.js",  
    "start": "node build/dev-server.js",  
    "build": "node build/build.js",  
~rest omitted~

Now the Vue app is shown when you access port 8080.
http://yourdomain.com:8080/

For other ways to use forever, see this post.
