Tuning Apache's event MPM

posted: 2018-05-26

Apache

Switching from prefork to event changes the tuning approach a bit, so here’s a quick note.

With the event MPM, the idea is that multiple Apache child processes (hereafter “processes”) are created first,
and then multiple worker threads (hereafter “threads”) are created inside each process.

The settings mean the following

<IfModule mpm_event_module>  
  ServerLimit               8 #Maximum number of processes  
  StartServers              3 #Initial number of processes  
  MinSpareThreads         192 #Minimum number of idle threads (increase when below)  
  MaxSpareThreads         384 #Maximum number of idle threads (decrease when above)  
  ThreadsPerChild          64 #Threads per process  
  MaxRequestWorkers       512 #Maximum number of simultaneous requests  
  MaxConnectionsPerChild 5000 #Requests a process handles before restarting  
</IfModule>
  • Keep MaxRequestWorkers at or below the maximum number of threads (ServerLimit × ThreadsPerChild).
    Receiving more requests than there are threads is a problem.
  • Keep MinSpareThreads at or below the initial number of threads (StartServers × ThreadsPerChild).
    If you need more idle threads than the initial count, threads have to be added right after startup, which is wasteful.
  • It seems better for MinSpareThreads and MaxSpareThreads to be multiples of ThreadsPerChild.
