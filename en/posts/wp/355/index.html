[CentOS + Apache] Getting and Auto-Renewing a Free SSL Certificate with Let’s Encrypt

posted: 2017-01-18

CentOS
Apache

■Environment

CentOS 7.3
Apache 2.4.6

Get a free SSL certificate with Let’s Encrypt and configure it to renew automatically.

■Prerequisites

The target server must be exposed to the internet.
→It seems Let’s Encrypt accesses the server for verification when issuing a certificate.
　Therefore, certificates cannot be issued in environments that block external access with a firewall or similar.
　As of 2017/1/19, the IP addresses used for that access are not published.
　https://letsencrypt.jp/faq/#IP (Japanese)

Setup Steps

*The following steps are performed with root privileges.

First, download the tool for obtaining certificates from Let’s Encrypt into any directory on the server.
If git isn’t installed on the server, you could download it locally and upload it via FTP or similar.

# git clone https://github.com/letsencrypt/letsencrypt

After downloading, perform the tool’s initial setup.
The following commands install the required software and so on, and display the letsencrypt-auto help when finished.

# cd letsencrypt  
# ./letsencrypt-auto --help --debug

Next, run the tool to actually obtain the certificate.
It errors out if a process is using port 443, so I had to stop Apache at that moment.

# systemctl stop httpd  
# ./letsencrypt-auto certonly --standalone -d your-domain.com  
# systemctl start httpd

*Replace “your-domain.com” above with the domain to generate the certificate for.

The certificate has now been generated.
The certificate and private key (symbolic links to them) are generated under the following directory,
so specify them in the Apache configuration file.
■Generated directory

/etc/letsencrypt/live/your-domain.com/

■Generated files

cert.pem　：　the SSL certificate itself  
chain.pem　：　the chain certificate  
fullchain.pem　：　the SSL certificate and chain certificate combined  
privkey.pem　：　the private key

Set these in the Apache configuration file (typically /etc/httpd/conf.d/ssl.conf).
・Configuration pattern 1

SSLCertificateFile /etc/letsencrypt/live/your-domain.com/cert.pem  
SSLCertificateKeyFile /etc/letsencrypt/live/your-domain.com/privkey.pem  
SSLCertificateChainFile /etc/letsencrypt/live/your-domain.com/chain.pem

・Configuration pattern 2

SSLCertificateFile /etc/letsencrypt/live/your-domain.com/fullchain.pem  
SSLCertificateKeyFile /etc/letsencrypt/live/your-domain.com/privkey.pem

*If your Apache version is 2.4.8 or later, the “SSLCertificateChainFile” setting can’t be used,
　so set fullchain.pem in “SSLCertificateFile”.

The certificate generated here is only valid for 3 months, so it needs to be renewed periodically.
The command to renew the certificate is as follows.

./letsencrypt-auto renew

However, renewal apparently only runs when fewer than 30 days remain before expiration,
so running the command above finishes without renewing anything.

Create a shell script that does “stop Apache → renew certificate → start Apache”.
It does nothing if a certificate generated within the last 70 days exists.

#!/bin/bash  
serchResult=`find /etc/letsencrypt/archive/your-domain.com/ -mtime -70 -regex ".*cert[0-9]?\.pem"`  
if [ -n "$serchResult" ]; then  
    echo "certs are not due for renewal yet"  
else  
    systemctl stop httpd && /opt/git/letsencrypt/letsencrypt-auto renew && systemctl start httpd  
    if [ $? != 0 ]; then  
        # just to be sure  
        systemctl restart httpd  
    fi  
fi

*The above assumes the tool is placed under opt.

Configure cron to run this script every day late at night.

# SSL update  
5 0 * * * sh /etc/letsencrypt/renew.sh

*The above is an example where the script was created at /etc/letsencrypt/renew.sh.

That completes the setup.
