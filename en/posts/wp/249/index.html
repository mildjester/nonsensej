[Apache] Keeping GET Parameters in .htaccess Rewrites

posted: 2016-05-26

Apache

These days nginx is on the rise, but this is about Apache.
I got stuck a bit, so here’s a note.

■Environment
CentOS 6.6
httpd 2.2.15

When writing a redirect in .htaccess,
if you write it as follows, the GET parameters are dropped on redirect.

RewriteEngine on}  
RewriteBase /  
RewriteRule ^api.php(.*)$ api2.php$1

For example, accessing “https://sample.com/api.php?name=tanaka" with this
redirects to “https://sample.com/api2.php".

To handle GET parameters in a rewrite, use “RewriteCond” as follows.

RewriteEngine on  
RewriteBase /  
RewriteCond %{QUERY_STRING} (.*)$  
RewriteRule ^api.php$ api2.php?%1

Now accessing “https://sample.com/api.php?name=tanaka"
redirects to “https://sample.com/api2.php?name=tanaka".
*Note that the right side of the RewriteRule uses “%1”, not “$1”. Don’t mix them up.

What’s happening is that the GET parameters matching the regex specified for “QUERY_STRING” in RewriteCond
are stored in % variables.
For example, you can also write:

RewriteEngine on  
RewriteBase /  
RewriteCond %{QUERY_STRING} name=(.*)$  
RewriteRule ^api.php$ api2.php?onamae=%1

Now accessing “https://sample.com/api.php?name=tanaka"
redirects to “https://sample.com/api2.php?onamae=tanaka".

You can also capture multiple parameters with a regex, so if you write

RewriteCond %{QUERY_STRING} param1=([a-z]+)&amp;param2=([a-z]+)&amp;param3=([a-z]+)$

you can get param1 as “%1”, param2 as “%2”, and param3 as “%3”.
