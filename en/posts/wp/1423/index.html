When Apache RewriteRule Didn't Work Behind AWS ELB

posted: 2018-06-30

AWS
Apache

■Environment

AWS ELB
AWS EC2
Apache 2.2.32

This is about an Apache server running on AWS EC2.

For SEO purposes, I wanted to redirect /index.html to /,
so I added the following to .htaccess.

RewriteRule ^(.*)index.html$ $1 [R=301,L]

It worked fine on the staging instance, but when I applied it to the production instance,
https://〜/index.html (port 443) started redirecting to http://〜/ (port 80).

Wondering why, I tried creating a branch like the following, but the result was the same.

# Set the protocol to http for now  
RewriteRule .* - [E=X_PRTCL:http]  
# If the request protocol is https, make the redirect target https as well  
RewriteCond %{HTTPS} on  
RewriteRule .* - [E=X_PRTCL:https]  
RewriteRule ^(.*)index.html$ %{ENV:X_PRTCL}://%{HTTP_HOST}/$1 [R=301,L]

The reason port 443 (https) traffic was treated as port 80 (http)
was that the production EC2 was behind an ELB.

In other words, the staging environment was

PC  
↓port 443  
EC2

whereas the production environment was

PC  
↓port 443  
ELB  
↓port 80  
EC2

When going through an ELB, it seems you need to look at the X-Forwarded-Proto parameter to determine the HTTP protocol.
https://docs.aws.amazon.com/elasticloadbalancing/latest/classic/x-forwarded-headers.html

Writing the following in htaccess made it work even through the ELB

# Set the protocol to http for now  
RewriteRule .* - [E=X_PRTCL:http]  
# If the request protocol is https, make the redirect target https as well  
RewriteCond %{HTTPS} on [OR] # For when not going through the ELB  
RewriteCond %{HTTP:X-Forwarded-Proto} https # For when going through the ELB  
RewriteRule .* - [E=X_PRTCL:https]  
RewriteRule ^(.*)index.html$ %{ENV:X_PRTCL}://%{HTTP_HOST}/$1 [R=301,L]
