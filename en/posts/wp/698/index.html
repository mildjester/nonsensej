[WordPress] CSS Specified by a Theme Fails to Load

posted: 2017-08-21

Wordpress

When using a theme made by someone else in WordPress, the CSS sometimes fails to load.
It seems to happen when both of the following apply:

  • The WordPress admin screen and the public site use different domains
  • The theme contains CSS files other than style.css and loads them with wp_enqueue_style

In that case, if you open the console in your browser’s developer tools, you’ll probably see an error like this:

Access to Font at 'http://yourdomain1.com/wp-content/themes/sparkling/assets/fonts/glyphicons-halflings-regular.woff2' from origin 'http://yourdomain2.com' has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present on the requested resource. Origin 'http://yourdomain2.com' is therefore not allowed access.

The cause seems to be cross-domain access, but I wanted a quick fix,
so I made the following changes.

  1. Comment out the wp_enqueue_style calls. (Depends on the theme, but usually in function.php or similar.)
// wp_enqueue_style( 'bs', get_template_directory_uri() . '/assets/css/bootstrap.min.css' );  
// wp_enqueue_style( 'awe', get_template_directory_uri() . '/assets/css/font-awesome.min.css' );
  1. Load the CSS inside the HTML head tag. (Depends on the theme, but usually in header.php or similar.)
    *The example below uses a CDN.
<link rel="stylesheet" href="//netdna.bootstrapcdn.com/font-awesome/4.0.3/css/font-awesome.min.css">  
<link rel="stylesheet" href="//maxcdn.bootstrapcdn.com/bootstrap/3.2.0/css/bootstrap.min.css">

With this, the CSS loaded correctly and the errors disappeared from the browser console.
