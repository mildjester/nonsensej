続カッコの付け方 (Japanese)

WordPress also looks at the request URL and fetches CSS over https only when accessed via https,
but because AWS ELB changes the port to 80, the following happens:

(1) Open an HTTPS WordPress page in Chrome
(2) WordPress returns CSS and other resources to be fetched over HTTP
(3) Chrome complains: “Resources on an HTTPS page must be fetched over HTTPS!”

*I also wrote about ELB-related issues here
When Apache RewriteRule Didn’t Work Behind AWS ELB

Solution: As in the article above, WordPress (as of Ver 4.1.1) also checks $_SERVER[‘HTTPS’],
so you can solve it by overwriting it in the Apache configuration (.htaccess also works).

# Enable HTTPS when the ELB receives the request over https  
SetEnvIf X-Forwarded-Proto ^https$ HTTPS=on  
  
# Redirect http access to https (optional)  
RewriteEngine on  
RewriteCond %{HTTP:X-Forwarded-Proto} ^http$  
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [R,L]
