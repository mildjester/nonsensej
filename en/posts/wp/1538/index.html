Automatic Deployment with CircleCI

posted: 2018-10-13

CircleCI

Circle CIでwebサイトを自動デプロイ (Japanese)

This is how to deploy to a server when changes are merged into the GitHub master branch.
The source code is assumed to be PHP.

It assumes the basic CircleCI setup described here has already been completed.
Running Unit Tests on Pull Requests with Circle CI

Preparing a CI user

First, create a key pair for SSH connections from CircleCI to the deployment server.
An existing key pair would also work, but it’s safer to use a separate one for CI.

ssh-keygen -t rsa -b 4096 -C "ci@hogehoge.com" -f ~/.ssh/ci-key

Running the command above asks for a passphrase twice; just press Enter for both and leave them empty.

Once key generation is complete, ci-key (private key) and ci-key.pub (public key) are created under .ssh in your home directory.
ci-key.pub is used in a later step, so check its contents.
*The command above specifies ci-key as the key file name, but any name is fine.

Next, create a user for deployment on the deployment server,
and allow SSH connections with the key pair you just created.
An existing user would also work, but it’s safer to use a separate one for CI.

adduser -g nginx ciuser  
su - ciuser  
mkdir .ssh  
vim .ssh/authorized_keys  
// Paste the contents of ci-key.pub

CircleCI dashboard settings

Next, configure settings in the CircleCI web console.
On the project’s screen, click Settings (gear icon) to open the settings screen.

SSH Key settings

From the left menu, open “PERMISSIONS > SSH Permissions” and click “Add SSH Key”.

A popup opens, so set the following.
Hostname : Host name of the deployment server
Private Key : The entire contents of the ci-key you created first

When done, the Fingerprint of the key you just registered is displayed, so make a note of it.
(It’s used later when editing the CircleCI config file)

Environment variable settings

You can use environment variables in the CircleCI config file edited later, so set them up.
This step isn’t required.
If you want to reuse the config file, it may be a good idea to make the environment-dependent parts environment variables.

From the left menu, open “BUILD SETTINGS > Environment Variables” and click “Add Variable”.

A popup opens, so register the variable name and value you want.
For example, setting the value ciuser for a variable named USER_NAME looks like the figure below.

Editing the CircleCI config file

Add the following lines to the .circleci/config.yml created last time.
The examples below use many of the environment variables from the previous step, but you can also write values directly in config.yml.

First, register the key information (fingerprint) for connecting to the deployment server.
Assume the following environment variable is set.
KEY_FINGERPRINT : The fingerprint of the SSH key you checked earlier

      - add_ssh_keys:  
          fingerprints:  
            - "${KEY_FINGERPRINT}"  
          # If you don't use environment variables, just hardcode it like this      
          # - "a1:b2:c3:・・・:x8:y9:z0"

Next, configure things so the SSH connection doesn’t fail.
Assume the following environment variables are set.
SSH_PORT : SSH port of the deployment server
HOST_NAME : Host name of the deployment server

      - run:  
          name: Start ssh-keyscan  
          command: |  
            ssh-keyscan -p ${SSH_PORT} ${HOST_NAME} >> ~/.ssh/known_hosts

Next, deploy.
In addition to the environment variables above, assume the following are set.
USER_NAME : User name for deployment (ciuser)
APP_PATH : Deployment path (/var/www/html etc.)
*CircleCI automatically sets ${CIRCLE_BRANCH} to the branch currently being processed.

      - deploy:  
          name: Start master deploy  
          command: |  
            if [ "${CIRCLE_BRANCH}" == "master" ]; then  
                rsync -av --delete --rsh="ssh -p ${SSH_PORT}" --exclude='.git' --exclude='.circleci' ./ ${USER_NAME}@${HOST_NAME}:${APP_PATH}  
            fi

The finished config.yml looks like this.

# PHP CircleCI 2.0 configuration file  
#  
# Check https://circleci.com/docs/2.0/language-php/ for more details  
#  
version: 2  
jobs:  
  build:  
    docker:  
      # specify the version you desire here  
      - image: circleci/php:7.1-fpm-node-browsers  
        
      # Specify service dependencies here if necessary  
      # CircleCI maintains a library of pre-built images  
      # documented at https://circleci.com/docs/2.0/circleci-images/  
      # - image: circleci/mysql:9.4  
  
    working_directory: ~/repo  
  
    steps:  
      - checkout  
  
      # Download and cache dependencies  
      - restore_cache:  
          keys:  
          - v1-dependencies-{{ checksum "composer.json" }}  
          # fallback to using the latest cache if no exact match is found  
          - v1-dependencies-  
  
      - run: composer install -n --prefer-dist  
  
      - save_cache:  
          paths:  
            - ./vendor  
          key: v1-dependencies-{{ checksum "composer.json" }}  
          
      # run tests!  
      - run: vendor/phpunit/phpunit/phpunit tests/  
  
      - add_ssh_keys:  
          fingerprints:  
            - "${KEY_FINGERPRINT}"  
  
      - run:  
          name: Start ssh-keyscan  
          command: |  
            ssh-keyscan -p ${SSH_PORT} ${HOST_NAME} >> ~/.ssh/known_hosts  
   
      - deploy:  
          name: Start master deploy  
          command: |  
            if [ "${CIRCLE_BRANCH}" == "master" ]; then  
                rsync -av --delete --rsh="ssh -p ${SSH_PORT}" --exclude='.git' --exclude='.circleci' ./ ${USER_NAME}@${HOST_NAME}:${APP_PATH}  
            fi

*Note
If you leave the SSH port at the default (22),
you don’t need to specify the SSH port in the ssh command in config.yml.

Now a deployment runs whenever you merge into master.
