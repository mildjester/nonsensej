Running Docker Toolbox & docker-compose on Windows

posted: 2018-09-21

Windows
Docker

At work I had Windows users set up a Docker environment,
and it was quite a struggle, so I’m writing down the steps.

■□ Note ■□■□■□■□■□■□■□■□■□■□■□■□■□■□■□
These steps assume you can already use docker-compose normally on Mac or Linux.
I won’t explain much about Docker or docker-compose themselves.
□■□■□■□■□■□■□■□■□■□■□■□■□■□■□■□■□■□

If you are using Windows 10 64-bit (anything other than Home), you don’t need to do any of this.
Install Docker for Windows instead of Docker Toolbox.
(Docker for Windows is probably easier to set up.)

Installing Docker Toolbox

First, download Docker Toolbox.
Download it from the following page.
https://docs.docker.com/toolbox/overview/#ready-to-get-started

Run the downloaded EXE file to launch the installer,
and just keep clicking Next.

When the installation finishes, a shortcut called “Docker Quickstart Terminal”
is created on the desktop. Run it.
After a while, Docker starts up. (An ASCII-art whale is displayed.)

Creating docker-compose.yml

Write a docker-compose.yml.
The basic syntax is the same as on Mac or Linux, so I’ll skip it.

What you need to be careful about is how you write volumes.
With relative paths, you can write them the same way as on other OSes:

volumes:  
    ./php.ini:/etc/php.ini

With absolute paths, write “C:¥” as “/c/”.
For example, to share the directory at “C:¥develop¥app”, write it like this:

volumes:  
    /c/develop/app:/var/www/html

Depending on the VirtualBox shared folder settings described later, you might be able to do it differently,
but to keep things as simple as possible, I do it this way.

If you create a MySQL container,
you cannot specify a host-side directory for data persistence.

In other words, this does NOT work:

services:  
  mysql:  
    ~snip~  
    volumes:  
      - ./mysql/data:/var/lib/mysql

But this works:

services:  
  mysql:  
    ~snip~  
    volumes:  
      - mydb:/var/lib/mysql  
    ~snip~  
  
volumes:  
  mydb

VirtualBox Settings

This is probably where people get stuck the most when running containers with Docker Toolbox.

Port Forwarding Settings

Just setting port forwarding to 8080:80 in docker-compose.yml
does not mean that accessing http://localhost:8080 on your local PC will send
the request to the Docker container.

This is because when you run containers with Docker Toolbox on Windows,
“a virtual machine is created in VirtualBox on Windows, and the Docker containers run inside it."

In other words, the port forwarding in docker-compose.yml
only covers VirtualBox => Docker container,
so you need to configure Windows => VirtualBox port forwarding separately.

First, open VirtualBox and click “Settings”.

Next, click “Network > Advanced > Port Forwarding”.

The port forwarding rules are displayed. Click the add button to add rules.
What you configure here is Windows => VirtualBox port forwarding, so if the port forwarding in docker-compose.yml is 8080:80,
you set 8080:8080 here.
Overall, the traffic is forwarded like
“Windows(8080) => VirtualBox(8080) => Docker(80)”.

Shared Folder Settings

Configure which folders on the host PC are shared with Docker.
This is the same as the “File Sharing” setting in Docker for Mac.
In the VirtualBox settings screen, select “Shared Folders” and click the add button to add a shared folder.
C:¥Users is shared by default, so you only need this if you put your source code outside your home directory.

In the add dialog, configure the following
■Folder Path
　The path of the folder you want to share.
　Click the “∨” mark on the right to open a selection window.
■Folder Name
　A name for the shared folder.
　Using the folder path separated by slashes is usually easiest to understand.
