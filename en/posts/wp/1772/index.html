Serving WordPress Images via S3 + CloudFront

posted: 2018-12-11

Wordpress
AWS

Environment

WordPress 4.8.3

AWS Setup Steps

IAM Settings

First, prepare an IAM user to connect WordPress with AWS.
In this procedure, permissions are granted through the bucket policy,
so the IAM-side permission settings can be anything.

Note down the following for the IAM user you prepared:

  • ARN
  • Access key ID
  • Secret access key

S3 Settings

Next, create a bucket for WordPress in S3
and set the following bucket policy:

{  
    "Version": "2012-10-17",  
    "Statement": [  
        {  
            "Sid": "AllowBucketAccess",  
            "Effect": "Allow",  
            "Principal": {  
                "AWS": "arn:aws:iam::ARN-of-the-prepared-IAM-user"  
            },  
            "Action": [  
                "s3:GetBucketLocation",  
                "s3:ListBucket",  
                "s3:PutObject",  
                "s3:PutObjectAcl",  
                "s3:GetObject",  
                "s3:DeleteObject"  
            ],  
            "Resource": [  
                "arn:aws:s3:::target-bucket/*",  
                "arn:aws:s3:::target-bucket"  
            ]  
        }  
    ]  
}

CloudFront Settings

You could let users fetch images directly from S3,
but the data transfer cost gets fairly high, so we route access to S3 through CloudFront.

First, click “Create Distribution” on the CloudFront console.

Next, click “Get Started” under Web.

In “Origin Domain Name”, specify the S3 bucket you want to serve through CloudFront.
It looks like a text box, but clicking it shows a list of choices.
Once you select the “Origin Domain Name”, “Origin ID” is filled in automatically.

After entering the above, scroll to the bottom and click “Create Distribution”.

You will be returned to the CloudFront list.
Wait until the Status of the distribution you just created becomes “Deployed”.

S3 is now accessible via CloudFront.
The domain to access it is shown under “Domain Name” in the figure above.

If you want to use a custom domain,
open the edit screen from “Distribution Settings” in the top menu
and configure it as follows:

Route 53 Settings

If you use CloudFront with a custom domain, configure DNS as well.

WordPress Settings

First, set up WordPress as usual.
(Steps omitted here.)

Plugin: Amazon Web Services

Install “Amazon Web Services” from Add New Plugins.

Next, set the IAM access keys in wp-config.php.
(Replace “AAA…” and “BBB…” below with your own values.)

define( 'DBI_AWS_ACCESS_KEY_ID', 'AAAAAAAAAAAAAAAAA' );  
define( 'DBI_AWS_SECRET_ACCESS_KEY', 'BBBBBBBBBBBBBBB' );

WordPress can now work with AWS.

Plugin: WP Offload Media Lite

Next, install “WP Offload Media Lite” from Add New Plugins.

After installing and activating it, “Offload Media” is added to the Settings menu.
Specify the bucket to use there.
Selecting it via “Browse existing buckets” at the bottom left is the easiest way.

After selecting the bucket, several settings appear.
By default, image URLs point directly to S3,
so change “Custom Domain” to the CloudFront URL.
(xxxxx.cloudfront.net or the custom domain you specified)

If you don’t want to keep image files on the server,
turn on “Remove Files From Server”.

*Note
As the Warning in the figure above says, some plugins may not work properly
unless the image files remain on the server.
In that case, either turn this off or deal with the plugin side.

Migrating Existing Image Files to S3

I used this as a reference:
https://php-java.com/archives/2228 (Japanese)

First, upload the existing image files to S3,
keeping the hierarchy like “wp-content/uploads/2018/…”.

Next, update the DB with SQL.
Replace the following parts of the SQL to match your environment:
webserver_hostname: host name of the web server
cloudfront_hostname: host name of CloudFront

The following assumes the S3 region is Tokyo.
If it isn’t, replace the S3 host name accordingly.

First, replace the image URLs in post content:

UPDATE wp_posts  
SET post_content = REPLACE(post_content, "https://webserver_hostname/wp-content/uploads/", "https://cloudfront_hostname/wp-content/uploads/");

Next, replace the featured image URLs:

UPDATE wp_posts  
SET guid = REPLACE(guid, "https://webserver_hostname/wp-content/uploads/", "https://cloudfront_hostname/wp-content/uploads/");

Next, add the S3 information for each image file to the meta information.
(INSERT, not UPDATE)

The following SELECT statement generates the INSERT statements;
running the generated INSERT statements completes the process.
Replace s3_bucket_name in the SQL with your target bucket name.
Also, if your S3 bucket isn’t in the Tokyo region, replace ap-northeast-1 as well.

SELECT  CONCAT('insert into wp_postmeta(post_id, meta_key, meta_value) values('  
, post_id, ', \'amazonS3_info\', \'a:4:{s:8:\"provider\";s:3:\"aws\";s:6:\"region\";s:14:\"ap-northeast-1\";s:6:\"bucket\";s:14:\"s3_bucket_name\";s:3:\"key\";s:',length(meta_value) + 19,':\"wp-content/uploads/', meta_value, '\";}\');'  
) AS record from wp_postmeta where meta_key = '_wp_attached_file';

Depending on your WordPress version, the INSERT statement may need slight changes.
To find out exactly what to insert, the best approach is to upload a new image in WordPress once
and check the record added to the wp_postmeta table.
