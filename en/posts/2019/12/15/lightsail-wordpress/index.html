Building WordPress Yourself on Lightsail (Amazon Linux Edition)

posted: 2019-12-15

Wordpress
AWS

Environment

Amazon Linux AMI 2018.03 (lightsail)

*Added February 2020
certbot started behaving oddly on Amazon Linux on Lightsail,
so I also wrote a CentOS version.
See the article here

Lightsail can create instances with WordPress preinstalled,
but I didn’t really like the all-in-one Bitnami environment,
so I built a WordPress environment myself on an empty instance.

The environment is
nginx + php-fpm (PHP 7.2)

Creating the Instance

Create a Lightsail instance.

Platform: Linux/Unix
Blueprint: OS Only, Amazon Linux

Configuring the Instance

Configure the instance you created.

Open the Networking tab of the target instance and attach a static IP.
If you serve over HTTPS, also open TCP port 443 in the firewall.

Installing and Configuring Everything

Connect to the instance via SSH and run the following commands.

First, become root.

sudo -i

Install various packages.

yum install -y git nginx php72-fpm php72-bcmath php72-cli php72-common php72-devel php72-gd php72-json php72-mbstring php72-mysqlnd php72-pdo php72-xml mysql-server

nginx Configuration

Add an nginx config file.
The part of the file name before .conf can be anything.

vim /etc/nginx/conf.d/wordpress.conf

Write it as follows.
(The standard WordPress setup.)

server {
    listen 80;
    listen [::]:80;
    server_name  your-domain.jp;

    root   /usr/share/nginx/html;
    index  index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~\.php$ {
            fastcgi_split_path_info ^(.+\.php)(/.+)$;
            include fastcgi_params;
            fastcgi_index index.php;
            fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
            fastcgi_pass unix:/var/run/php-fpm/www.sock;
    }
}

PHP Configuration

Open the config file.

vim /etc/php.ini

Modify the following so image uploads work without trouble.

upload_max_filesize = 16M
post_max_size = 16M

php-fpm Configuration

Open the config file.

vim /etc/php-fpm.d/www.conf

Modify the following so it runs with nginx.

user = nginx
group = nginx

If you created a low-spec instance, adjust pm.max_... to match the instance’s capacity.

pm.max_children = 15
pm.max_spare_servers = 10

Starting nginx & php-fpm

Start

service nginx start
service php-fpm start

Enable auto-start

chkconfig nginx on
chkconfig php-fpm on

MySQL Configuration

Start and enable auto-start

service mysqld start
chkconfig mysqld on

Set the root password.
Replace new-password below with the password you want.

/usr/libexec/mysql55/mysqladmin -u root password 'new-password'

Let’s Encrypt Configuration

Get a free SSL certificate from Let’s Encrypt.
Replace your-domain.jp with the domain you use for WordPress.

cd /opt
git clone https://github.com/letsencrypt/letsencrypt
cd letsencrypt
./letsencrypt-auto certonly --webroot -w /usr/share/nginx/html -d your-domain.jp --debug

Once you have the SSL certificate, open the nginx config file again.

vim /etc/nginx/conf.d/wordpress.conf

Add the SSL settings.

server {
    〜省略〜
    listen  443 ssl http2;
    listen  [::]:443 ssl http2;

    ssl_certificate /etc/letsencrypt/live/your-domain.jp/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.jp/privkey.pem;
    〜省略〜
}

The foundation is now in place.
All that’s left is to download and configure WordPress, following the official WordPress site or similar.

Appendix: MySQL Commands

Create a user

CREATE USER 'wp-user'@'localhost' IDENTIFIED BY 'new-password';

Create a database

CREATE DATABASE wp-database character set utf8mb4;

Change a user’s password

UPDATE mysql.user SET password=password('new-new-password') where user = 'wp-user';
