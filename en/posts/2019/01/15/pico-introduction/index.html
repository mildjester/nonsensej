Introducing "pico", a PHP-Based CMS

posted: 2019-01-15

pico

What is pico

A CMS written in PHP that lets you create web pages with files alone, without using a database.
Official site

Pages can be written in Markdown, so I think it’s an easy-to-use CMS
for people who often take notes in Markdown.

How does it compare to WordPress

Ease of writing pages

It’s easy to write for people used to Markdown,
but it’s probably not a good fit if you hire writers who aren’t familiar with it.

Also, since expression is limited to what Markdown can do, WordPress, where you can write HTML directly,
may allow more freedom in rendering.
It turns out you can write HTML inside Markdown in pico too

Ease of setup

For a basic setup, you just grab the source code and you’re done, so it’s easy.
However, adding plugins can require editing theme files,
which is more work than WordPress, where you simply click “Install”.

Also, the lack of information in Japanese may be a bottleneck when setting it up.

Ease of management

There is no admin panel, so all configuration is done in the source code.
So it would be difficult for non-engineers to operate.

On the other hand, there’s no database, so managing backups is easy.
GitHub now lets you create private repositories for free,
so you can just manage everything there.

Also, since there’s no admin panel, I think it’s strong in terms of security.

Features

pico doesn’t have the tags and categories that WordPress provides by default,
so it’s a bit inconvenient.
You can add them with plugins, but it’s somewhat cumbersome.

WordPress also wins in the number of plugins and themes.

Installing pico

Creating the project

First, create a project with composer.
*If you don’t know composer, see here

composer create-project picocms/pico-composer pico

If you place the generated pico directory on a web server as is,
the default page is already displayed.
The default page explains how to place content and more,
so it’s worth reading.

URL rewrite settings

pico uses URL rewriting.
(It’s not required, but without it URLs look ugly, and it probably isn’t good for SEO either)

The URL rewrite rules are written in pico’s .htaccess.
.htaccess only works with Apache, so with Nginx you need separate configuration.
Official URL rewrite instructions

Creating the config file

Copy or rename pico/config/config.yml.template
to create pico/config/config.yml.

For the initial stage, these are probably the only settings you need to change.

Setting Value
site_title Change to your site’s title
timezone Asia/Tokyo if in Japan

*Caution
The default timezone is UTC, so you might think you should change it to JST,
but it has to be Asia/Tokyo.

Once you place config.yml, the default page is no longer displayed.
After that, pages are generated by creating md files under pico/content.
Pages are mainly created as follows.

pico/content/index.md
The so-called index page
Displayed when accessing https://your-pico-site.com/

pico/content/404.md
The so-called 404 page
(If you don’t create it, a default page is displayed. Create it if you want to customize it)

pico/content/hogehoge.md (hogehoge is arbitrary)
Displayed when accessing https://your-pico-site.com/hogehoge
In the default theme, it also appears in the page list at the top right

pico/content/fooooo/hogehoge.md (fooooo and hogehoge are arbitrary)
Displayed when accessing https://your-pico-site.com/fooooo/hogehoge
In the default theme, it does not appear in the page list at the top right

Each page’s md file consists of “YAML header + content”.
For example, it looks like this.

---
title: サンプルページ
summary: これはサンプルページですよ
date: 2019-01-07
draft: false
---

これはサンプルページですよー

For details on the YAML header, see the official page.
YAML header explanation on the official page

For Template above, specify the name of a Twig file provided in the current theme.
(The default theme is pico/themes/default)
For example, in the example above, the template used is index.twig.

To turn it into a blog, continue to Building a Blog with pico.
