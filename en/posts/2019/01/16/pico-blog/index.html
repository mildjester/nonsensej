Building a Blog with Pico

posted: 2019-01-16

pico

For the basic setup of Pico, see the following.
Introducing Pico, a PHP-based CMS

This post explains how to build a blog with Pico.
The official site describes the steps for turning Pico into a blog.
Official instructions

The official method seems to create a blog section within a website,
so if the main content of your site is the blog itself, modify it as follows.

I have also published the finished result as a template.
If you just want to set up a blog quickly, feel free to use it.
mildjester/pico-blog

Adding Plugins

Download plugins into pico/plugins.

Pagination

https://github.com/rewdy/Pico-Pagination/releases
The downloaded archive contains pagination.php,
so place it in /pico/plugins.

Then add the plugin settings to config.yml.

##
# Plugin: Pico-Pagination
#
pagination_limit: 10           # Number of posts per page on list pages
pagination_next_text: 次へ>>  # Text for the "next" link
pagination_prev_text: <<戻る  # Text for the "previous" link

Tags

https://github.com/PontusHorn/Pico-Tags
Place PicoTags.php in /pico/plugins.

Site Search

https://github.com/mwgg/Pico-Search
Place 40-PicoSearch.php in /pico/plugins.
This plugin seems to let you search by page title,
but not by the article body.

Sitemap

https://github.com/DaveKin/Pico_Sitemap/
Place PicoXMLSitemap.php in /pico/plugins.

Editing the Theme

Edit the theme under /pico/themes.
You can edit the default /pico/themes/default directly,
or copy default to create your own theme.

If you create a separate theme, also change theme: default in config.yml to the directory name of your theme.

You can also download themes from the official site. However, perhaps because they are themes for Pico 1.x, some of them don’t work as-is, so be careful.
Theme list on the official site

Splitting index.twig

By default, index.twig contains the entire HTML,
which hurts maintainability as you add more templates,
so split out the header and footer.

First, create _header.twig in the same directory as index.twig,
and copy from the first line of index.twig down to just above <div id="main">.
Next, likewise create _footer.twig and copy from just below the closing tag of <div id="main">
to the last line.

Then delete the copied header and footer parts from index.twig,
and replace them with {% include '_header.twig' %} and {% include '_footer.twig' %}.

The resulting index.twig looks like this.

{% include '_header.twig' %}
<div id="main">
    <div class="container">
        {% if meta.title %}<h2>{{ meta.title }}</h2>{% endif %}
        <p class="meta">{{ meta.date_formatted }}</p>
        {{ content }}
    </div>
</div>
{% include '_footer.twig' %}

Note: How much to share is a matter of personal preference,
so feel free to adjust the shared range.

Adding a Site Search Form to the Header

Embed the following code anywhere you like in the header.
This becomes the site search form.

<form id="search_form" action="/search" method="get">
    <input type="search" id="search_input" name="q" />
    <input type="submit" value="検索" />
</form>

Creating Per-Page Templates

Create the following twig files in the same directory as index.twig.

index.twig

Displays a list of all posts.

{% include '_header.twig' %}
<div id="main">
    <div class="container">
        {% for page in paged_pages|sort_by("time")|reverse %}
            {% if page.id starts with "posts/" and not page.hidden %}
                <div class="post">
                    <h3><a href="{{ page.url }}">{{ page.title }}</a></h3>
                    <p class="date">{{ page.date_formatted }}</p>
                    <p class="excerpt">{{ page.description }}</p>
                </div>
            {% endif %}
        {% endfor %}
        {{ pagination_links }}
    </div>
</div>
{% include '_footer.twig' %}

article.twig

Displays a post page.

{% include '_header.twig' %}
<div id="main">
    <div class="container">
        {% if meta.title %}<h2>{{ meta.title }}</h2>{% endif %}
        <p class="meta"><b>
            投稿日：{{ meta.date_formatted }}
            <span class="article_tags">
                タグ：
                {% for tag in meta.tags %}
                <a href="/tags/{{ tag }}" >{{ tag }}</a> 
                {% endfor %}
            </span>
        </b></p>
        {{ content }}
    </div>
</div>
{% include '_footer.twig' %}

static.twig

Displays a static page.
Note: The page title and date are hidden.

{% include '_header.twig' %}
<div id="main">
    <div class="container">
        {{ content }}
    </div>
</div>
{% include '_footer.twig' %}

tags.twig

Displays the list of tags.

{% include '_header.twig' %}
<div id="main">
    <div class="container">
        {% if meta.title %}<h2>{{ meta.title }}</h2>{% endif %}
        <ul>
        {% for page in pages %}
            {% if page.id starts with "tags/" and not page.hidden %}
                    <li><a href="{{ page.url }}">{{ page.title }}</a></li>
            {% endif %}
        {% endfor %}
        </ul>
    </div>
</div>
{% include '_footer.twig' %}

tag-index.twig

Displays a list of posts filtered by tag.

{% include '_header.twig' %}
<div id="main">
    <div class="container">
        {% if meta.title %}<h2>{{ meta.title }}</h2>{% endif %}
        {% for page in pages|sort_by("time")|reverse %}
            {% if page.id starts with "posts/" and not page.hidden %}
                <div class="post">
                    <h3><a href="{{ page.url }}">{{ page.title }}</a></h3>
                    <p class="date">{{ page.date_formatted }}</p>
                    <p class="excerpt">{{ page.description }}</p>
                </div>
            {% endif %}
        {% endfor %}
    </div>
</div>
{% include '_footer.twig' %}

search.twig

Displays site search results.

{% include '_header.twig' %}
<div id="main">
	<div class="container">
		<div class="SearchResults">
			{% if meta.purpose == "search_results" %}
					<p class="meta">「{{ search_term }}」の検索結果（{{ search_num_results }} 件）</p>
					{% for page in search_results %}
						{% if page.id starts with "posts/" and not page.hidden %}
							<h3><a href="{{ page.url }}">{{ page.title }}</a></h3>
							<p class="date">{{ page.date_formatted }}</p>
							<p class="excerpt">{{ page.description }}</p>
						{% endif %}
					{% endfor %}
			{% endif %}
		</div>
	</div>
</div>
{% include '_footer.twig' %}

Adjusting the Styles (CSS)

Also add styles for the tag list on post pages.
Add the following to css/style.css in the theme directory.

/* Tag list on post pages */
span.article_tags {
    margin-left: 40px;
    font-size: 0.9em;
}
span.article_tags a {
    border-radius: 5px;          /* CSS3 draft */  
    -webkit-border-radius: 5px;  /* For Safari, Google Chrome */  
    -moz-border-radius: 5px;     /* For Firefox */
    background-color: #707070;
    color: #ffffff;
    padding: 1px 7px;
}

The theme is now ready.

Creating the md Files

Now create the md files that make up the actual page content.

pico/content/index.md

The page listing all posts.

---
title: ブログ
summary: これはブログですよ
date: 2010-12-31
draft: false
---

pico/content/tags.md

The tag list page.

---
title: タグ一覧
summary: タグの一覧ページですよ
date: 2010-12-25
draft: false
---

pico/content/tags/sampleTag.md

The post list page for a tag.
In this example, it lists posts tagged sampleTag.

---
title: sampleTag
summary: sampleTagの一覧です
Filter: sampleTag
---

pico/content/posts/sampleArticles.md

A post page.
For Tags, specify tags created in pico/content/tags/ above.

---
title: 記事ですよ
summary: これは記事ページです
tags:
    - sampleTag
date: 2015-08-08 15:35:56
draft: false
---
記事の本文ですよー

pico/content/search.md

The site search results page.

---
Purpose: search_results
---

pico/content/hogehoge.md

A static page.
Create these as needed.
If you don’t need any static pages, you don’t have to create one.

---
title: 何かのページ
summary: 何か固定ページだよ
date: 2001-01-01
draft: false
---
固定ページですよー

That covers the basic md files you need.
If you don’t want Google or other search engines to index your pages,
add the following to the YAML header.

Robots: noindex,nofollow

Your Pico blog is now complete.

If you are migrating data from WordPress, see Migrating Data from WordPress to Pico.
