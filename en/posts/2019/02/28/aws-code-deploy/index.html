Deploying to EC2 with AWS CodeDeploy

posted: 2019-02-28

AWS

I introduced CodeDeploy to push source code to an EC2 instance I was running, so here are my working notes.
I tried it with a very simple setup, as follows:

  • Only one EC2 instance
  • No ELB
  • Source code is fetched from GitHub
  • Deployment just places the source code on the server
  • Deployments are run manually from the AWS console.

*For CircleCI integration, see here

Preparing IAM

Prepare roles for EC2 and for CodeDeploy.

First, create the role for EC2.
On the IAM role creation screen, choose AWS service > EC2 and proceed to the next step.

Select the AmazonEC2RoleforAWSCodeDeploy policy and proceed to the next step.

Tags are optional, so proceed to the next step if you don’t need them.

Enter a role name of your choice and click “Create role”.

Next, create the role for CodeDeploy.
On the IAM role creation screen, choose AWS service > CodeDeploy.

The screen scrolls down and shows the use case selection.
Since we are simply deploying to a volume on plain EC2, select CodeDeploy and proceed to the next step.

The AWSCodeDeployRole policy is shown, so just proceed to the next step.

Enter a role name of your choice and click “Create role”.

Preparing EC2

First, attach the role to the EC2 instance from the management console.
Open the target instance in the management console and click the following:
Actions > Instance Settings > Attach/Replace IAM Role

Set the EC2 role you created earlier.

Next, log in to the target instance from a terminal and install the CodeDeploy agent.
The installer you download won’t run without Ruby, so install it if it isn’t already installed.

$ sudo yum install ruby # if ruby is not installed
$ sudo yum install aws-cli # if aws-cli is not installed
$ aws s3 cp s3://aws-codedeploy-ap-northeast-1/latest/install . --region ap-northeast-1
$ chmod +x ./install
$ sudo ./install auto

Once installation is complete, check that it is running just in case.

$ sudo service codedeploy-agent status
The AWS CodeDeploy agent is running as PID 12345

If you started the CodeDeploy agent before attaching the role above,
just restart the CodeDeploy agent after attaching the role.

$ sudo service codedeploy-agent restart

Preparing the Repository

Create a file named appspec.yml at the top level of the git repository to deploy, with the following content.

version: 0.0
os: linux
files:
  - source: ./
    destination: /usr/share/nginx/html

This deploys the directory specified by source in the repository (the whole repository in the example above) to destination.
You can specify multiple source/destination pairs, and you can also add processing before and after deployment.
For details, see the official AWS page.

Push this to GitHub.

Configuring CodeDeploy

First, click “Create application”.

Enter an application name, select “EC2/On-premises” as the compute platform,
and click “Create application”.

Next, configure a deployment group to register with the application.
(Deployment group: a grouping of the EC2 instances and so on that are targeted during deployment.)

Although it’s called a group, this time we register just one EC2 instance.

First, click “Create deployment group”.

Enter a name for the deployment group.
For the service role, specify the CodeDeploy role you created earlier.

Scroll down to the “Environment configuration” section and specify the name of the existing EC2 instance.

Set the deployment configuration to “CodeDeployDefault.AllAtOnce” and click “Create deployment group”.
(Since there is only one target instance this time, it doesn’t really matter which one you choose.)

The deployment group is now created.

Running CodeDeploy

To actually push the source code to the server, create a deployment.
You can create a deployment from the deployment group screen.
(Below is the screen shown after the deployment group is created.)

On the deployment creation screen, first specify the deployment group you created earlier.

Next, choose GitHub as the revision type.
Fields for GitHub information appear; enter your GitHub account name as the GitHub token name
and click “Connect to GitHub”.

If an authorization screen appears on GitHub, authorize it.

Then enter the repository name and the commit ID you want to deploy to the server.
The repository name is in “account-name/repository-name” format, and the commit ID is the full, unabbreviated ID.

Next, in the additional deployment behavior settings, select “Overwrite the content”,
then click “Create deployment” to run the deployment.
*If you don’t specify overwriting, the deployment fails when existing content is present.

If the deployment fails midway, check the following agent log on the EC2 instance.

/var/log/aws/codedeploy-agent/codedeploy-agent.log
