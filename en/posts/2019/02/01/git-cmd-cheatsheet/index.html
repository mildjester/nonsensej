Git Command Cheat Sheet (Advanced)

posted: 2019-02-01

git

Advanced usage of git commands.
If you can do these, you might become an intermediate git user.

Remove Information About Deleted Remote Branches

Every time you pull, git fetches information about branches that exist on the remote.
(That’s the remote/xxxxx you see with git branch -a.)

A plain git pull fetches remote branches,
but does nothing about branches deleted on the remote,
so they remain locally as remote information.

To remove information about branches deleted on the remote from your local repository,
add the following option when pulling:

git pull --prune

Force Pull

Forcibly matches the branch state to the remote.
Useful when your local branch has gotten into a confusing state and you want to discard it,
or when pulling in something someone force-pushed to the remote.
(Though force-pushing to a branch shared by several people is evil…)

git fetch
git reset --hard origin/{branch name}

*Assumes the remote is origin.

Add Changes to the Previous Commit

A way to fold additional changes into the previous commit, e.g. when you missed a small fix.
This keeps the commit history from growing.

git add .
git commit --fixup=HEAD
git rebase -i --autosquash HEAD~2
(save and close the following rebase screen as-is)

★Caution★

If the previous commit has already been pushed,
you’ll need to force push after the commands above.
Force pushing to a branch shared with others
may prevent them from pulling.
Only do this on a branch that you alone are working on.

Squash Commit Logs Into One When Merging

When you want to commit in small increments while working,
you can create a working branch, commit freely there,
and consolidate the commit log into one when merging the working branch back into the original branch.

git merge --squash {branch to merge}
git commit

The original commit logs are included in the commit message by default,
but you can delete them.
(Keeping them is fine too.)

Check the Diff Between the Current Branch and master

This is what you see when sending a pull request on GitHub.
You can check it from the command line as well.

The b option ignores whitespace differences.

git diff -b origin/master

*Note
For ignoring whitespace in git diff, there are the b and w options,
which differ as follows:

Option Description “a=␣b” => “a=␣ ␣b” “a=b” => “a=␣b”
b Ignores changes in the amount of whitespace Ignored Not ignored
w Ignores all whitespace Ignored Ignored

*In the table above, “␣” represents a half-width space.

Check Changes to a Specific File Since a Specific Commit

Again, this is what you see when viewing commit logs on GitHub.

git diff -w {commit ID}...HEAD {file name}
e.g.: git diff -w 11b2233...HEAD app/Controller/HogeController.php

Also, though you may not use it much, if you want to show the entire file rather than just the changed lines,
specify a large number such as 10000 with the U option (which sets how many lines of context to show around changes).

git diff -w -U10000 {commit ID}...HEAD {file name}

Show a Slightly More Detailed Commit History

The stat option shows which files were changed in each commit.
The graph option also lets you see the branch merge history graphically.

git log --stat --graph

Create Aliases for git Commands

You can register aliases by adding something like the following to ~/.gitconfig:

[alias]
	co = checkout
	br = branch
	logs = log --stat --graph

With this, git co works the same as git checkout,
and git logs works the same as git log --stat --graph.
