Keeping Apache from Eating Up All Server Memory

posted: 2019-02-15

Apache

Environment

  • Amazon Linux AMI 2018.03
  • Apache/2.4.34 (Amazon)

Apache (prefork) was eating up all of the server’s memory, so I tuned it.
These are notes on the investigation and calculations I did.

If you can switch from prefork to event, or migrate to nginx,
that may be the better option.
This procedure assumes you’re tuning prefork.

Check the Server’s Physical Memory

First, check the server’s physical memory.

# cat /proc/meminfo | head -n 1
MemTotal:        2004484 kB

This server has 2GB of memory.

Check Current Memory Usage

First, check the memory used by the whole server.
Use the following one-liner (in MB):

# ps aux | awk '{print $6}' | awk '{sum=sum+($1/1024);cnt++;} END{print "sum="sum}'
sum=919.656

Next, check the memory used by httpd child processes.
Use the following one-liner (in MB):

# ps aux | grep httpd | grep apache | awk '{print $6}' | awk '{sum=sum+($1/1024);cnt++;} END{print "sum="sum " cnt="cnt " ave="sum/cnt;}'
sum=804.273 cnt=20 ave=40.2137

The output means the following:

Item Meaning
sum Total memory currently used by httpd child processes
cnt Number of httpd child processes
ave Average memory used by one httpd child process

*Note

The server’s total memory usage can also be obtained from /proc/meminfo mentioned above or the free command,
but those differ slightly from the ps results, so I use ps consistently.

Calculation

Let’s organize what we’ve found so far.

  • Server memory = about 2GB … (1)
  • Current total memory used = about 920MB … (2)
    • Of which, memory used by Apache child processes = about 800MB … (3)
    • Memory used by everything other than Apache child processes = about 120MB … (4) ((2) - (3))
  • Memory used per Apache child process = about 40MB … (5)

From here, a rough calculation:

  • Memory to reserve for things other than Apache child processes = 500MB … (6) (very rough, with plenty of margin, based on (4))
  • Memory for Apache child processes = about 1500MB … (7) ((1) - (6))
  • Number of Apache processes that can be spawned = about 35 … (8) ((7) / (5))

Set this in the Apache configuration.

<IfModule mpm_prefork_module>
StartServers               5
MinSpareServers            5
MaxSpareServers           10
ServerLimit               35 #Changed to the result calculated above
MaxClients                35 #Changed to the result calculated above
MaxConnectionsPerChild     0
</IfModule>

If your existing Apache configuration files have no section like the above,
you can append it to httpd.conf or create a new configuration file under /etc/httpd/conf.d/.

I also wanted about 20 httpd child processes running at all times, among other things,
so I ended up with the following settings:

<IfModule mpm_prefork_module>
StartServers              20 #Start 20 processes when httpd starts
MinSpareServers            5
MaxSpareServers           20 #Allow up to 20 idle processes waiting for requests
ServerLimit               35
MaxClients                35
MaxConnectionsPerChild  5000 #Have child processes be reborn after handling a certain amount
</IfModule>
