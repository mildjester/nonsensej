Building WordPress Yourself on Lightsail (CentOS Edition)

posted: 2020-02-18

Wordpress
AWS

Environment

  • CentOS Linux release 7.6.1810 (Core)
  • nginx 1.1.17
  • php 7.4.2
  • MySQL 8.0.19

In a previous post I built WordPress on Amazon Linux,
but for some reason certbot stopped working properly on Lightsail’s Amazon Linux,
so I decided to rebuild it on CentOS.

Creating the Instance

Create a Lightsail instance.

Platform: Linux/Unix
Blueprint: OS Only, CentOS

Instance Settings

Configure the instance you created.

Open the Networking tab of the instance and attach a static IP.
If you are going to serve over HTTPS, also open TCP port 443 in the firewall.

Logging In to the Server & Initial Setup

Connect to the instance via SSH and run the following commands.

First, become root.
All subsequent commands are assumed to be run as root.

$ sudo -i

Set the time zone to Japan.

# timedatectl set-timezone Asia/Tokyo

Install some basic applications.

yum install git vim

Disabling SELinux

SELinux can prevent various things from working, so disable it.
(e.g. nginx returning 403)
If you want a properly secure environment, you should make everything work with SELinux enabled,
but I didn’t need that much this time, so I’m skipping it.

Check whether it is currently enabled.
If the following command prints “Enforcing”, it is enabled.

# getenforce
Enforcing

Edit the config file to disable it.

# vim /etc/selinux/config
Change the following line:
SELINUX=disabled

Restart the instance from the Lightsail console to apply the change.

Installing nginx

Follow the official instructions.
http://nginx.org/en/linux_packages.html#RHEL-CentOS

# yum install yum-utils

# vim /etc/yum.repos.d/nginx.repo
~An empty file opens; write the following~
[nginx-stable]
name=nginx stable repo
baseurl=http://nginx.org/packages/centos/$releasever/$basearch/
gpgcheck=1
enabled=1
gpgkey=https://nginx.org/keys/nginx_signing.key
module_hotfixes=true

[nginx-mainline]
name=nginx mainline repo
baseurl=http://nginx.org/packages/mainline/centos/$releasever/$basearch/
gpgcheck=1
enabled=0
gpgkey=https://nginx.org/keys/nginx_signing.key
module_hotfixes=true
~End~

# yum-config-manager --enable nginx-mainline
# yum install nginx

Configuring nginx

Add an nginx config file.
The part of the file name before .conf can be anything.

vim /etc/nginx/conf.d/wordpress.conf

Write the following.
(The usual WordPress setup.)

server {
    listen 80;
    listen [::]:80;
    server_name  your-domain.jp;

    root   /usr/share/nginx/html;
    index  index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~\.php$ {
            fastcgi_split_path_info ^(.+\.php)(/.+)$;
            include fastcgi_params;
            fastcgi_index index.php;
            fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
            fastcgi_pass unix:/var/run/php-fpm/www.sock;
    }
}

Installing PHP

Run the following commands.
This example installs PHP 7.4. For a different version,
change the remi-phpxx part of the repository enabled in yum install.

# yum install epel-release
# rpm -Uvh http://rpms.famillecollet.com/enterprise/remi-release-7.rpm
# yum install --disablerepo=* --enablerepo=epel,remi,remi-safe,remi-php74 -y php-fpm php-bcmath php-cli php-common php-devel php-gd php-json php-mbstring php-mysqlnd php-pdo php-xml

Configuring PHP

Open the config file.

# vim /etc/php.ini

Change the following so that image uploads work without trouble.

upload_max_filesize = 16M
post_max_size = 16M

Configuring php-fpm

Open the config file.

# vim /etc/php-fpm.d/www.conf

Change the following so it works with nginx.

user = nginx
group = nginx

listen = /var/run/php-fpm/www.sock

listen.owner = nginx
listen.group = nginx
listen.mode = 0660

If you created a small instance, adjust pm.max_* to match the instance’s capacity.

pm.max_children = 15
pm.max_spare_servers = 10

Starting nginx & php-fpm

Start

# systemctl start nginx.service
# systemctl start php-fpm.service

Enable auto-start

# systemctl enable nginx.service
# systemctl enable php-fpm.service

Installing MySQL

CentOS comes with MariaDB installed by default, so remove it.

# yum remove mariadb-libs
# rm -rf /var/lib/mysql  * Delete it if it exists. It may not exist if MariaDB has never been started.

Install MySQL.

# yum install https://dev.mysql.com/get/mysql80-community-release-el7-2.noarch.rpm
# yum install mysql-community-server

If you start MySQL as is, you get the following error.

Cannot allocate memory for the buffer pool

This is because Lightsail has no swap space.
If you check, swap should be zero.

# free -m
              total        used        free      shared  buff/cache   available
Mem:            485          74         247           8         163         358
Swap:             0           0           0

Allocate swap space.
The example below creates 512 blocks of 1MB = 512MB of swap.

# dd if=/dev/zero of=/swapfile bs=1M count=512
# chmod 600 /swapfile
# mkswap /swapfile
# swapon /swapfile

Checking again, the swap has been created.

# free -m
              total        used        free      shared  buff/cache   available
Mem:            485          73           5           8         406         359
Swap:           511           0         511

As is, the swap will be released when the server restarts, so add it to fstab as well.

# vim /etc/fstab
~Add the following line~
/swapfile                                 swap                    swap    defaults        0 0

Starting MySQL & Enabling Auto-start

systemctl start mysqld.service
systemctl enable mysqld.service

Changing the MySQL root Password

The initial root password is in the log.
Check the hogehoge part below.

# grep "temporary password" /var/log/mysqld.log
A temporary password is generated for root@localhost: hogehoge

Set the root password.

mysql -u root -p
Enter password: (enter the initial password you found)
ALTER USER 'root'@'localhost' IDENTIFIED BY 'new-password';

Let’s Encrypt Setup

Get a free SSL certificate with Let’s Encrypt.
Please refer to this post.
[Let’sEncrypt] How to Use Certbot (CentOS7 + nginx)

The infrastructure part is now done.
All that’s left is to download and configure WordPress, following the official WordPress site or similar.
