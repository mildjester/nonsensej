Allowing AWS Lambda to Access Both a Database and External Services

posted: 2020-07-12

AWS

To let AWS Lambda access AWS RDS, you add the Lambda function to a VPC subnet that can reach RDS.
However, a Lambda function inside a VPC loses external access unless you do something about it.

This is a problem when Lambda needs to use external system APIs as well as RDS,
so configure the VPC so that Lambda inside it can access external services.

VPC Configuration

How to give a Lambda function in a VPC external access is actually explained officially by AWS.
Basically, you just need to follow these steps.
https://aws.amazon.com/premiumsupport/knowledge-center/internet-access-lambda-function/

For details, see the official page; here I’ll just outline the flow.
For ① and ②, you can reuse existing resources if you already have them.

① (If none exists) Create a VPC that can access RDS.
② (If none exists) Create an internet gateway and attach it to the VPC from ①.
③ Create two subnets in the VPC that can access RDS (one public, one private).
④ Create a new NAT gateway and associate it with the public subnet created in ③.
⑤ Create a new route table and associate it with the public subnet.
　Once created, add the following route.

Item Value
Destination 0.0.0.0/0
Target The internet gateway from ②

⑥ Create another new route table and associate it with the private subnet.
　Once created, add the following route.

Item Value
Destination 0.0.0.0/0
Target The NAT gateway from ④

That’s it for the VPC configuration.
If you add the Lambda function to the private subnet created here, it can access both RDS and external services.

Lambda Configuration (Serverless Framework)

This time I build the Lambda function with the Serverless Framework.
For the basic setup with the Serverless Framework, see my previous post.

Add the vpc setting to the provider section of the serverless.yml created in the previous post.

provider:
  ~omitted~
  vpc: 
    subnetIds:
      - ID of the private subnet created here (subnet-0123456abcde)

[Bonus]
Not covered in the VPC configuration above, but if you want to assign a security group to the Lambda function, do the following.

provider:
  ~omitted~
  vpc: 
    subnetIds:
      - ID of the private subnet created here (subnet-0123456abcde)
    securityGroupIds:
      - ID of the security group to assign (sg-012345abcde)
