How to Set Up Redirects with AWS S3

posted: 2020-06-10

AWS

This is a configuration for redirecting access to specific paths to another server,
for example when you’ve partially moved static content hosted on AWS S3 to a different server.

In the target S3 bucket, under
“Properties” > “Static website hosting” > “Use this bucket to host a website”
there is a field called Redirection rules; configure it as follows.

This example sets up redirection rules (RoutingRule) ① to ③.

<RoutingRules>
  <RoutingRule>　　　・・・①
    <Condition>
      <KeyPrefixEquals>kokojanai_dokoka.html</KeyPrefixEquals>
    </Condition>
    <Redirect>
      <Protocol>https</Protocol>
      <HostName>new-server.co.jp</HostName>
      <ReplaceKeyWith>kokodayo.html</ReplaceKeyWith>
    </Redirect>
  </RoutingRule>
  <RoutingRule>　　　・・・②
    <Condition>
      <HttpErrorCodeReturnedEquals>403</HttpErrorCodeReturnedEquals>
    </Condition>
    <Redirect>
      <Protocol>https</Protocol>
      <HostName>new-server.co.jp</HostName>
    </Redirect>
  </RoutingRule>
  <RoutingRule>　　　・・・③
    <Condition>
      <HttpErrorCodeReturnedEquals>404</HttpErrorCodeReturnedEquals>
    </Condition>
    <Redirect>
      <Protocol>https</Protocol>
      <HostName>new-server.co.jp</HostName>
    </Redirect>
  </RoutingRule>
</RoutingRules>

① Access to a Specific Path

When a specific path is accessed, the path is rewritten and redirected.
Useful when the path changed after moving from S3 to a new server.

The values to set are as follows.

Setting Description Sample value
KeyPrefixEquals Redirects when this path is accessed. kokojanai_dokoka.html
Protocol Protocol of the redirect destination https
HostName Host name of the redirect destination new-server.co.jp
ReplaceKeyWith Replaces the KeyPrefixEquals value with this value. kokoday.html

In the sample, assuming the S3 bucket is served under the DNS name s3-sample.co.jp,
access to https://s3-sample.co.jp/kokojanai_dokoka.html
is redirected to https://new-server.co.jp/kokodayo.html.

②③ Access to Paths That Don’t Exist on S3

When a path that doesn’t exist on S3 is accessed, it is redirected to another server with the same path.
Useful when you’ve moved content from S3 to a new server while keeping the same paths.
② and ③ are identical except for HttpErrorCodeReturnedEquals.

Setting Description Sample value
HttpErrorCodeReturnedEquals The HTTP response code from S3 that triggers the redirect 403 and 404*
Protocol Protocol of the redirect destination https
HostName Host name of the redirect destination new-server.co.jp

*For paths that don’t exist on S3, it seems S3 may return 403 as well as 404, so I’ve included both just in case.

In the sample, assuming the S3 bucket is served under the DNS name s3-sample.co.jp,
access to https://s3-sample.co.jp/hoge.html
is redirected to https://new-server.co.jp/hoge.html.
