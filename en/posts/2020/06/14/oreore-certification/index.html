Creating a Self-Signed Certificate on EC2

posted: 2020-06-14

AWS
Linux

Environment

  • Amazon Linux AMI 2017.03
  • OpenSSL 1.0.2k-fips 26 Jan 2017

Let’s create a self-signed certificate, which has seen much less use since Let’s Encrypt came along.

Let’s Encrypt SSL certificates are more trusted and require no configuration on the browser side.
Even in environments not exposed to the internet, you can issue a Let’s Encrypt certificate by adding a TXT record to DNS.

These steps are for those who still want to use a self-signed certificate.

What Is a Self-Signed Certificate?

SSL certificates are normally issued after being certified by some certificate authority (CA),
but here you set up your own CA and issue an SSL certificate certified by yourself.

The rough flow is as follows.

  1. Set up your own CA
  2. Issue your own certificate with that CA
  3. Make your browser trust your CA

The following steps assume creating a wildcard SSL certificate for “*.hoge.com”.
Replace “*.hoge.com” with the domain you want to create.

Prepare the Working Directory

Log in to EC2 via SSH and prepare as follows.
The self-made CA will be created in a directory called hogeCA.

sudo -i
cd /etc/pki
cp -r CA hogeCA
cp tls/openssl.cnf hogeCA/.
cd hogeCA
touch index.txt
echo "00" > serial

Also, I don’t think this used to be required,
but recent browsers apparently won’t accept a certificate as valid unless SAN (subjectAltName) is set.
Create a file for setting the SAN.

echo "subjectAltName=DNS:*.hoge.com" > san.ext

Modify the openssl Configuration

Modify the openssl.cnf used this time as follows.

vim ./openssl.cnf

Modify the [ CA_default ] Section

Change the working directory.

dir             = /etc/pki/hogeCA

Modify the [ req_distinguished_name ] Section

Since you’ll be asked for the company location and such several times in these steps, set default values.

countryName_default             = JP
stateOrProvinceName_default     = Tokyo
localityName_default            = Toshima-ku
0.organizationName_default      = Hoge Co. Ltd.

Modify the [ usr_cert ] Section

This setting loads the SAN.

subjectAltName=@alt_names

Build the Certificate Authority (CA)

Create the CA Private Key

Generate a private key for the CA.
You’ll be asked for a password for the private key; enter one.

openssl genrsa -aes256 -out ./private/cakey.pem 2048

Create the CA CSR (Certificate Signing Request)

Create a CSR for issuing the CA certificate.
You’ll be asked for the password you set on cakey.pem; enter it.
After that you’ll be asked various questions. You can basically just press Enter, but for “Common Name” enter a CA name of your choice so you can identify it later.

openssl req -new -config ./openssl.cnf -key ./private/cakey.pem -out ./cacert.csr

Create the CA Certificate

Issue the CA certificate.
You’ll be asked for the cakey.pem password here too; enter it.

openssl x509 -days 825 -in ./cacert.csr -req -signkey ./private/cakey.pem -out ./cacert.pem

Issue the Server Certificate

Now issue the actual SSL certificate for the server.
To keep things easy to find later, first create a directory to store the SSL certificate files.

mkdir hoge_com

Create the SSL Private Key

Generate a private key for SSL.
Again, you’ll be asked for a password for the private key; enter one.
(You’ll remove the password right away, so anything is fine.)

openssl genrsa -aes256 -out ./hoge_com/server-with-password.key 2048

Create a password-less version of the private key from the generated one.
You’ll be asked for the password from the previous step; enter it.

openssl rsa -in ./hoge_com/server-with-password.key -out ./hoge_com/server.key

Create the SSL CSR

Create a CSR for issuing the SSL certificate.
You’ll be asked various questions. You can basically just press Enter, but for “Common Name” enter the domain to configure (*.hoge.com this time).

openssl req -new -config ./openssl.cnf -key ./hoge_com/server.key -out ./hoge_com/server.csr

Issue the SSL Certificate

Issue the SSL certificate.
You’ll be asked for the cakey.pem password; enter it.

openssl ca -config ./openssl.cnf -in ./hoge_com/server.csr -out ./hoge_com/server.crt -days 825 -extfile san.ext

After the command above, you’ll be asked two y/n questions; answer y to both.

Sign the certificate? [y/n]:y
1 out of 1 certificate requests certified, commit? [y/n]y

Web Server Configuration

Configure the generated SSL certificate on the web server.
For Apache it looks like this.

SSLCertificateFile /etc/pki/hogeCA/hoge_com/server.crt
SSLCertificateKeyFile /etc/pki/hogeCA/hoge_com/server.key

Browser Configuration

To display the SSL certificate created here without errors,
import the CA certificate (/etc/pki/hogeCA/cacert.pem) into your browser.

In Chrome, you can import the CA certificate with the following steps.

  1. Download the CA certificate to your local machine.
  2. In Chrome, click “Settings > Privacy and security > (More) > Manage certificates”
  3. Click “Import” on the Authorities tab, then select and import cacert.pem.
  4. A trust settings window opens; check “Trust this certificate for identifying websites” and click “OK”.

Now pages using the self-signed certificate will open without errors.
