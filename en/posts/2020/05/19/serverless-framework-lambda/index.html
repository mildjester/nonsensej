Deploying Lambda & API Gateway with the Serverless Framework

posted: 2020-05-19

AWS

Environment

ubuntu 20.04 LTS

The Serverless Framework is a tool that makes it easy to build serverless environments.
https://www.serverless.com/framework/docs/

This time I’ll use it to build a serverless API on AWS using Lambda & API Gateway.

Preparation (Setting Up awscli)

The Serverless Framework deploys using the aws cli, so you need to install it.
If awscli is already usable on your work PC, you can skip this section.

Install awscli

Follow the steps on the official page.
https://docs.aws.amazon.com/cli/latest/userguide/install-cliv2-linux.html

$ curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip"
$ unzip awscliv2.zip
$ sudo ./aws/install

awscli is now installed.
Check the version just in case.

$ aws --version
aws-cli/2.0.14 Python/3.7.3 Linux/5.4.0-31-generic botocore/2.0.0dev18

Prepare an Access Key

Generate an access key for awscli in AWS IAM.
The steps are on the official page.
https://docs.aws.amazon.com/cli/latest/userguide/cli-chap-configure.html#cli-quick-configuration

Roughly, you do the following.

  1. Go to IAM
  2. Select the user to issue the access key for.
  3. Click “Create access key” on the “Security credentials” tab.
  4. Note down the displayed access key ID / secret access key.

That’s it.

Configure awscli

Set the access key obtained from IAM and the region in awscli.

$ aws configure
AWS Access Key ID [None]: YOUR-ACCESS-KEY-ID
AWS Secret Access Key [None]: YOUR-SECRET-ACCESS-KEY
Default region name [None]: ap-northeast-1
Default output format [None]:

*If you press Enter with the output format left empty, it defaults to json.

If you use multiple AWS accounts, you can specify the profile to store the access key in by running the following.
Replace profile01 below with any profile name you like.

$ aws configure --profile profile01

Now you can use awscli while switching between profiles.

Setting Up the Serverless Framework

Install the Serverless Framework

Follow the steps on the official page.
https://www.serverless.com/framework/docs/getting-started/

On ubuntu (Linux), run the following command.

curl -o- -L https://slss.io/install | bash

Load a Serverless Framework Template

Run the serverless command in your working directory and answer a few questions to load a template for the Serverless Framework.
In the example below, the Lambda language is python and the service name is sw-test.
*The sls command is short for the serverless command

$ sls
Serverless: No project detected. Do you want to create a new one? Yes
Serverless: What do you want to make? AWS Python
Serverless: What do you want to call this project? sw-test

Project successfully created in 'sw-test' folder.

You can monitor, troubleshoot, and test your new service with a free Serverless account.

Serverless: Would you like to enable this? No
You can run the “serverless” command again if you change your mind later.


Serverless: Would you like to setup a command line <tab> completion? No

This creates the sw-test directory with the Serverless Framework template loaded into it.

Configure the Serverless Framework

Add configs for the staging/production environments to the generated template so that per-environment variables can be defined.
The file structure looks like this.

sw-test
 ├─conf            ・・・config directory (added)
 │  ├─dev.yml     ・・・staging environment config (added)
 │  └─prd.yml     ・・・production environment config (added)
 ├─handler.py      ・・・script run by Lambda (this time we use the template sample as-is)
 └─serverless.yml  ・・・file defining what to deploy

The file contents are as follows.

[dev.yml]
Just the region for now.

region: us-west-2

[prd.yml]
Just the region for now.

region: ap-northeast-1

[serverless.yml]

service: sw-test

custom:
  default_stage: dev
  stage: ${opt:stage, self:custom.default_stage}              If no stage is specified at deploy time, dev is used.
  config_file:
    dev: ${file(./conf/dev.yml)}
    prd: ${file(./conf/prd.yml)}
  config: ${self:custom.config_file.${self:custom.stage}}     Loads dev.yml or prd.yml depending on the stage.

provider:
  name: aws
  runtime: python3.8
  region: ${self:custom.config.region}                        Reads the contents of dev/prd.yml. Settings other than region in the config file can be referenced the same way.

functions:
  hello:
    handler: handler.hello                                    Calls the hello method in handler.py when the events specified below occur
    events:
      - http:
          path: hello                                         Path that receives requests
          method: get

If you specify http in the functions’ events as above, API Gateway is deployed together with Lambda.

■Gotcha
Indentation is two spaces throughout, but only the path: hello line is indented four spaces from the hyphen of - http:.
In other words, the correct indentation seems to be two spaces deeper than http:.
(This may be obvious to people used to YAML, but it tripped me up a bit.)

If this is wrong, you’ll get the following error when deploying.

Serverless Error ---------------------------------------
 
  Missing or invalid "path" property in function "hello" for http event in serverless.yml. If you define an http event, make sure you pass a valid value for it, either as string syntax, or object syntax. Please check the indentation of your config values if you use the object syntax. Please check the docs for more options.

Deploy

If you separated awscli profiles, specify the profile first.

export AWS_PROFILE="profile01"

Deploy.

sls deploy

If no errors occur, the application has now been added to Lambda and API Gateway in the staging region.
To release to production, deploy with the stage specified as follows.

sls deploy --stage prd

That’s all.
