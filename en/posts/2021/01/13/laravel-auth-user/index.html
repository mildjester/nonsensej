Auth::user() Sometimes Works and Sometimes Doesn't Inside a Laravel Queue

posted: 2021-01-13

Laravel

Environment

  • Laravel 5.8

I created an event listener in Laravel that “sends the updater’s information in an alert email when data is updated”,
but inside it, the value of Auth::user() was either the updater’s information or null depending on the environment.

The processing registered in this event listener was set up to be pushed onto a queue and processed asynchronously,
and naturally you can’t get user information with Auth::user() in asynchronous processing.
So getting null was the expected behavior.

So why could the user information be retrieved in some environments?
The cause was the value of QUEUE_DRIVER in .env.

With QUEUE_DRIVER=database and the like, queued jobs are processed asynchronously,
but with QUEUE_DRIVER=sync, queued jobs are processed synchronously.

When the queue runs synchronously, the job runs while the user information is still available via Auth::user(),
so if you set QUEUE_DRIVER=sync in your local environment, Auth::user() works inside the queue.

This can also be caught by testing in an environment whose .env properly matches production,
so don’t release based only on local verification; test in a production-equivalent environment as well.
